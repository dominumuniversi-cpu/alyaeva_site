| Конец | закрывается | только уточняется |
| Пример | «#26 нужны ключи» | «сначала `nginx -t`, потом reload» |

**Где что живёт (24.11.2026):**

## ЛОВУШКА: метод не совпал — 405 «Method Not Allowed» (23.11.2026)

Владелец открыл `/logout` и получил `{"detail":"Method Not Allowed"}`.

**Причина:** обработчик объявлен только как `@app.post("/logout")`, а ссылка в меню — `<a href="/logout">`,
то есть обычный **GET**. FastAPI отвечает 405.

**Правило:** если на действие ведёт ссылка из меню — вешать **оба** декоратора:

    @app.get("/logout")
    @app.post("/logout")
    def logout(request: Request): ...

Или делать кнопку с формой (тогда только POST). Но не оставлять разрыв.

**Проверять** действие не только «глазами», а запросом того метода, который реально шлёт браузер:
`curl -D- -o /dev/null https://alyaeva.pro/logout` → должно быть 303, а не 405.

## ЛОВУШКА: NOT NULL на необязательном поле (23.11.2026)

`users.phone` был `NOT NULL`. Регистрация без телефона падала с **500 NotNullViolation** —
и это было не видно, потому что все тестовые регистрации указывали номер.

**Правило:** поле обязательно в схеме только если без него бизнес-смысл невозможен.
Телефон для входа по e-mail — **не** такой случай. Миграция 005 сняла NOT NULL,
`create_user` пишет `NULL`, а не пустую строку.

**Проверять:** регистрация с пустыми необязательными полями — отдельный тест.

**ЛОВУШКА: `position: sticky` внутри контейнера с `overflow: hidden` не работает (24.11.2026).**

## ПРОВЕРКА СТИЛЕЙ: БРАУЗЕР ПОД SYSTEM НЕ РАБОТАЕТ (24.11.2026)

«200 OK» ≠ «страница выглядит нормально»: `/login` год жил без CSS. Проверять надо отдельно.

| Что | Как |
|---|---|
| CSS отдаётся | `https://alyaeva.pro/static/app.css` = 200 и в нём есть правила |
| Без браузера (по умолчанию) | тянем CSS и сверяем классы в отданном HTML — этого хватает для цветов и токенов |
| С браузером | `node scripts\check-styles.js` — **только от имени пользователя**, не от SYSTEM |

**Почему не работает из-под агента:** Edge закрывается с кодом **1002** даже с `--headless=new`.
Под учётной записью SYSTEM браузер не стартует. Раньше `check-styles.js` вообще падал на
`Cannot find module`: puppeteer в проекте не было. Теперь стоит `puppeteer-core` (в `package.json`)
и берётся установленный Edge — но запуск от SYSTEM всё равно упирается в 1002.

Значит: проверку браузером запускает **владелец** или планировщик от пользователя, а агент
не выдаёт «проверено скриптом» за правду — пишет, что проверял классами и запросами.

Ловушки, которые скрипт уже ловил:
- в CSS `#4B4690`, браузер отдаёт `#4b4690` — сравнивать без учёта регистра;
- главная задаёт шрифт на `div#top`, а не на `body` — проверять оба;
- неудачный вход молча пропускал проверку админки — итог обязан честно писать, что проверено.

## ИНСТРУМЕНТЫ: ЧЕМ ДЕЛАТЬ, А НЕ ТОЛЬКО ЧЕМ ПРОВЕРЯТЬ (24.11.2026)

В `scripts/` лежат готовые инструменты. Прежде чем писать руками — посмотреть, есть ли готовый.

| Что нужно | Инструмент | Заметка |
|---|---|---|

| Проверить, что ни одна страница не падает | `node scripts\smoke.js --user <email> --ask-pass` | обходит кабинет и админку; код 1 при любой 5xx |
| Понять, на каком слое обрыв | `node scripts\diagnose-site.js` | контейнер → прокси → сертификат → браузер |
| Проверить стили браузером | `node scripts\check-styles.js` | **только от имени пользователя**: под SYSTEM Edge падает с кодом 1002 |
| Вахта за сайтом | `node scripts\watchdog.js` | пишет тревогу в лог, код 1 при падении |
| Бэкап базы и фото | `node scripts\backup.js` | задача в планировщике, 03:30 |
| Продление сертификата | `node scripts\renew-cert-guarded.js` | задача в планировщике; трогает `proxy` только если ≤30 дней |

### Деплой и 502 — подробности в `docs/deploy.md`

Коротко: `proxy_pass` на приложение и на статику — **только через переменную** + `resolver` в том же
`server`, иначе nginx держит старый IP контейнера и сайт уходит в 502 на минуты. После каждого
переключения: `nginx -t` → `reload` → `check-live.js`.

Замеры, ловушка со статикой, окно простоя (единицы секунд; владелец разрешил), страница
«Сайт обновляется» вместо 502 и почему рестарт контейнера не заменяет пересборку образа — в `docs/deploy.md`.

## СЧЁТЧИК ПОСЕЩЕНИЙ: ГЛАВНАЯ САМА СООБЩАЕТ О ЗАХОДЕ (24.11.2026)

Главная — статический файл, nginx отдаёт её мимо приложения. Поэтому приложение не знает,
что человек на неё зашёл, и в статистике была пустая строка `page`.

| Что | Как |
|---|---|
| Приём события | `GET /api/visited?p=/` — только страницы из `STATIC_PAGES` в `main.py` |
| Отправка | пиксель в конце `build/dist/index.html` |
| Свой визит | заголовок `X-DSH-Check: 1` — событие не пишется |

Новая статическая страница со счётчиком → добавить её путь в `STATIC_PAGES`, иначе приём откажет.
Белый список не случаен: свободный текст в `page` — это мусор в базе.

**Проверяя сайт своими запросами, ставь `X-DSH-Check: 1`.** 24.11.2026 мои же проверки дали
81 просмотр за час и чуть не стали «выводом о поведении людей». Тестовые события после проверок удалять.

**Отключает он НЕ всё — проверено 24.11.2026.** Заголовок глушит только приём визита главной
(`/api/visited`). **Переходы по страницам приложения и открытия формы заказа он не глушит:** они
пишутся в `site_events` прямо в шаблонах (`_events.html`). За один прогон `smoke.js` под админом
набежало 68 просмотров и 2 «открыл заказ» — почти всё это мои собственные проверки.

| Что остановит «набежавшие» просмотры | Как |
|---|---|
| Заголовок `X-DSH-Check: 1` | только `/api/visited`, то есть главная |
| Вход со страницы-проверки | переходы по `/cabinet`, `/admin/...`, `/order` всё равно считаются |
| Уборка после проверки | `DELETE FROM site_events WHERE created_at > now() - interval '…'` — **только** свои события, за точный отрезок |

**Правило:** после проверок с входом смотреть `site_events` и удалять только то, что набежало
за время проверки. Раздел «Откуда пришли» иначе врёт, и решение принимается по мусору.
