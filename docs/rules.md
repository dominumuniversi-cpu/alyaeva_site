## ЛОВУШКА: метод не совпал — 405 «Method Not Allowed» (23.11.2026)

Владелец открыл `/logout` и получил `{"detail":"Method Not Allowed"}`.

**Причина:** обработчик объявлен только как `@app.post("/logout")`, а ссылка в меню — `<a href="/logout">`,
то есть обычный **GET**. FastAPI отвечает 405.

**Правило:** если на действие ведёт ссылка из меню — вешать **оба** декоратора:

    @app.get("/logout")
    @app.post("/logout")
    def logout(request: Request): ...

Или делать кнопку с формой (тогда только POST). Но не оставлять разрыв.

**Проверять** действие не только «глазами», а запросом того метода, который реально шлёт браузер:
`curl -D- -o /dev/null https://alyaeva.pro/logout` → должно быть 303, а не 405.

## ЛОВУШКА: NOT NULL на необязательном поле (23.11.2026)

`users.phone` был `NOT NULL`. Регистрация без телефона падала с **500 NotNullViolation** —
и это было не видно, потому что все тестовые регистрации указывали номер.

**Правило:** поле обязательно в схеме только если без него бизнес-смысл невозможен.
Телефон для входа по e-mail — **не** такой случай. Миграция 005 сняла NOT NULL,
`create_user` пишет `NULL`, а не пустую строку.

**Проверять:** регистрация с пустыми необязательными полями — отдельный тест.

**ЛОВУШКА: `position: sticky` внутри контейнера с `overflow: hidden` не работает (24.11.2026).**
На главной шапка стояла внутри блока-обложки, у которого `overflow: hidden` (обрезал декоративные
шарики). Стиль `sticky` был написан — и всё равно **не работал**: контейнер с `overflow` отменяет липкость

| Симптом | Причина | Проверка |
|---|---|---|
| шапка уезжает при прокрутке | `sticky` внутри `overflow:hidden`/`auto`/`scroll` или внутри `transform` | посчитать незакрытые `<div>` перед `<header>` в отданной странице |

**Правило:** шапка живёт сразу после `<body>`, декоративные обёртки — ниже. Проверять **разметкой
отданной страницы**, а не поиском `sticky` в файле: `sticky` в источнике ничего не значит.

**Шапка статических страниц.** Новая статическая страница получает шапку и подвал **копией с главной** и `<link rel="stylesheet" href="/assets/header.css">` — иначе меню на телефоне будет работать иначе (24.11.2026: на `/fotokniga-ekaterinburg/` шапки не было вовсе).

**Ссылки мессенджеров:** главная и лендинг — шаблоны приложения (`app/pages/web/`), берут адреса из настроек `/admin/settings`.

## ПРОВЕРКА СТИЛЕЙ И ВЁРСТКИ: БРАУЗЕР — В КОНТЕЙНЕРЕ (обновлено 24.11.2026, задача #221)

«200 OK» ≠ «страница выглядит нормально»: `/login` год жил без CSS. Проверять надо отдельно.

| Что | Как |
|---|---|
| CSS отдаётся | `https://alyaeva.pro/static/app.css` = 200 и в нём есть правила |
| Без браузера (по умолчанию) | тянем CSS и сверяем классы в отданном HTML — этого хватает для цветов и токенов |
| С браузером | `node scripts\check-styles.js` — **только от имени пользователя**, не от SYSTEM |

**На хосте браузера нет**, и это не мешает: браузер запускается **в контейнере**.
Edge на хосте под SYSTEM закрывается с кодом 1002 — туда не лезем.

```
docker run --rm --network npc-proxy-net -v E:/!Develop/sites/alyaeva:/w:ro \
  mcr.microsoft.com/playwright:v1.49.0-jammy node /w/_проба.mjs
```

Внутри: `import puppeteer from "/w/node_modules/puppeteer-core/lib/puppeteer/puppeteer-core.js"`
(путь **без** `esm/`), браузер — `/ms-playwright/chromium-1148/chrome-linux/chrome`,
флаги `--no-sandbox --disable-dev-shm-usage`. Снимки — только в смонтированный каталог, `/w` для записи закрыт.

Ловушки, которые скрипт уже ловил:
- в CSS `#4B4690`, браузер отдаёт `#4b4690` — сравнивать без учёта регистра;
- главная задаёт шрифт на `div#top`, а не на `body` — проверять оба;
- неудачный вход молча пропускал проверку админки — итог обязан честно писать, что проверено.

**Что мерить (вёрстка, а не цвет):** у каждого элемента `getBoundingClientRect()` — высота, `top`, `left`.
Меню админки на ширинах 1280 / 820 / 390 должно дать `[8]` / `[4,4]` / `[1×8]` строк (задача #221).
Цели пальца на 390 px — не меньше 44 px (#223). Кнопка «Наверх» — скрыта наверху, видна после прокрутки (#226).


**Ловушка замера прокрутки.** На сайте `html{scroll-behavior:smooth}`: `window.scrollTo(0, N)`
запускает **анимацию**, и `scrollY` сразу после вызова показывает середину пути. Меряя прилипание шапки
или глубину прокрутки — сначала `document.documentElement.style.scrollBehavior = "auto"`, иначе
вывод будет неверным. (24.11 я дважды принял это за «страница не листается» — запись 18.)

## СТАТУСЫ ЗАКАЗА: СЛОВАРЬ И БД ДОЛЖНЫ СОВПАДАТЬ (24.11.2026)

В БД ограничение разрешало 5 старых статусов, а `order_status.py` знает 8.
Смена статуса в админке падала с **500** на «Макет», «Оплачен», «В печати», «Отправлен» —
три четверти пути заказа. Заметить это «просмотром страниц» невозможно: они открывались.

| Правило | Как |
|---|---|
| Добавил статус | сразу миграция, приводящая ограничение к `STATUS_NAMES` |
| Проверка | `POST /api/admin/order/{id}/status` **на каждом** статусе, а не на одном |
| Сверка | `SELECT pg_get_constraintdef(oid) FROM pg_constraint WHERE conname = orders_status_chk` |

**Путь вызова — с id в середине:** `/api/admin/order/{id}/status`.

Один и тот же список разъехался в проекте пять раз. Каждый раз страницы открывались,

## СОХРАНЕНИЕ БЕЗ ПЕРЕЗАГРУЗКИ: КАК УСТРОЕНО В АДМИНКЕ (24.11.2026, задача #215)

Правило владельца: действие не перезагружает страницу. Образец — `/admin/settings`:

| Что | Как |
|---|---|
| Маршрут | если в `Accept` есть `application/json` → `JSONResponse({"ok": True, "saved": "…"})`, иначе прежний `303` |
| Форма | `<form id="…" method="post">` без изменений — без JS работает как раньше |
| Скрипт | `fetch(form.action, {method:"POST", body:new FormData(form), credentials:"same-origin"})`, ответ → плашка `#…_msg` |
| Плашка | класс `save-msg` (+ `save-msg-ok` / `save-msg-bad`), `role="status"`, `aria-live="polite"` |
| Рядом с кнопкой | `div.btn-row` — кнопка и сообщение в одну строку с переносом |

**Ловушка CSRF:** форма залогиненного человека проходит заслон только со своим `Origin`. Проверяя форму
скриптом (python/curl), присылайте `Origin: https://alyaeva.pro`, иначе получите 403 и решите, что форма сломана.

## ГДЕ РЕДИРЕКТ УМЕСТЕН, А ГДЕ НЕТ (24.11.2026, задачи #215, #217)

Из 17 POST-маршрутов приложения страницу перезагружали три. Разбор:

| Маршрут | Редирект | Почему так |
|---|---|---|
| `/login`, `/logout` | остаётся | это переход «вошёл → в кабинет», а не правка на месте |
| `/admin/settings`, `/admin/hooks` | **убрано** | после сохранения человек остаётся там же, иначе теряет прокрутку и правки |

**Приём — один скрипт на все формы** (`app/static/form-save.js`): маршрут отвечает JSON, когда в `Accept` есть `application/json`, и прежним
`303` иначе; форма подключает скрипт строкой и рисует плашку `save-msg`. Новую форму не копировать — подключить:

```html
<span class="save-msg" id="f_x_msg" role="status" aria-live="polite"></span>
<script src="/static/form-save.js" data-form="f_x" defer></script>
``` Без JS всё работает как раньше —
это не украшение, а страховка на случай отключённых скриптов.

**Как проверять:** `POST` с `Accept: application/json` → JSON; `POST` с `Accept: text/html` → прежний переход.
Оба раза с `Origin: https://alyaeva.pro`, иначе CSRF-заслон отдаст 403.
