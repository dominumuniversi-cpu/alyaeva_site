# Integrations и модульность

Записано 26.11.2026 по вопросу владельца: «Как реализованы механизмы постов и сбор сообщений
со всех каналов в одно окно? Есть ли готовые решения на GitHub? Как хранятся секреты?
Можно ли взять отдельный модуль и использовать где-то ещё?»

## 1. Как это устроено сейчас (факты из кода)

### Единое окно (инбокс)

| Что | Где |
|---|---|
| Диалоги | таблица `message_threads` (канал + внешний id чата) |
| Сообщения | таблица `message_hub` (направление, канал, автор, текст, meta) |
| Запись входящего | `hooks.incoming() → orders.log_message()` |
| Чтение | `orders.threads()` / `orders.thread_messages()`, страница `/admin/inbox` |
| Ответ клиенту | `messaging.deliver()` → `send_telegram` / `send_vk` |

Канал-источник — **три** вида входящего: посещение/форма сайта, Telegram (опрос через прокси),
VK (одним из способов ниже).

### Посты (контент-завод)

| Шаг | Кто |
|---|---|
| Сборка текста | `posts.compose()` — текст + тема + цена из `pricing` + ссылка, обрезка по слову |
| Хранение | таблица `posts` (тело, каналы, статус, result) |
| Что можно публиковать | `posts.channels_ready()` (токен + адрес канала) |
| Очередь/история | `post_queue` — `create/save/delete/mark_result` |
| Отправка | `messaging.send_telegram` / `send_vk` |
| Экран | `/admin/posts` — лента, правка («Изменить»), публикация |

Отложенной публикации нет (нет планировщика) — это отдельная задача.

## 3. Секреты: как сейчас (это важно понять)

Логика: в `app_settings` (`key`/`value`) хранится ФАКТ и настройка; для секретов `value` = `enc:…`.

- **шифрование**: `secrets_helper.py`, Fernet (AES-128-CBC + HMAC-SHA256), ключ = SHA-256 от `SECRET_KEY` из окружения контейнера;
- **секретные ключи**: `telegram.token`, `telegram.hook_secret`, `vk.token` — `enc:`. `vk.confirm_code` и `vk.secret` пока пишутся открыто (комментарий в коде), потому что это не токены API;
- **кто разные**: шифртекст расшифровывается только внутри приложения на чтение ведёт каждый конкретный вызов;
- **смена SECRET_KEY = потеря шифртекств** (тогда токены вводятся заново) — это проверять нельзя легкомысленно, в бэкапе `.env` должен быть сохранён.

## 4. Модульность: можно ли взять отдельный модуль и использовать в другом месте?

**Пока НЕТ — это честный ответ.** Причины (все проверяемы в коде):

- все файлы лежат в `app/` и импортируют друг друга абсолютными именами (`import db`,
  `import messaging`, `from web_common import render`) — пакета с собственным именем нет;
- настройки — плоские ключи одной таблицы `app_settings` (нет пространства имён «модуль.хвост»);
- шифрование секретов привязано к `SECRET_KEY` сайта (тот же ключ на всё);
- страницы и шаблоны — часть сайта; отдельной сборки, которая поднимется «без сайта», нет;
- таблицы создаются одной сводной миграцией, а не миграцией модуля.

**Что уже похоже на модуль (можно выделять первыми):** `secrets_helper`, `messaging`, `post_queue`,
`tg_receiver`. Они зависят от небольшого числа точек (`db.get_setting`, `db.pool`, шаблоны — только в маршрутах).

**План переноса** — задача #294 с критерием «на чистой машине модуль поднимается в две команды».
