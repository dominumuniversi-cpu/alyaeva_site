# Заказ: только для вошедших

Правила решений владельца о том, кто и как может сделать заказ. Вынесено из `AGENTS.md`
24.11.2026 (файл правил перестал влезать в контекст сессии). Здесь — детали; в `AGENTS.md`
остались сам запрет и указатель на этот файл.


**Требование:** авторизованный идёт на страницу заказа; неавторизованному предлагаем войти и
после входа возвращаем **к заказу**, а не в кабинет.

### Как устроено

| Шаг | Что происходит |
|---|---|
| Гость → `/order` | `303` на `/login?next=/order&reason=order` |
| Страница входа | заголовок «Войдите, чтобы заказать» + скрытое поле `next` |
| Вход / регистрация | возврат на `_safe_next(next, "/cabinet")` |
| `POST /api/order` | без сессии → `401` + `{"login": true}`, JS уводит на вход |
| Загрузка фото | требует сессии, проверяет владельца (403 на чужой заказ) |

### Решение владельца: заказ только для вошедших — навсегда (24.11.2026)

На вопрос «гостю можно оставить заявку без регистрации?» владелец ответил: **нет**.
Это продуктовое решение, а не временное ограничение. Самостоятельно его не пересматривать.

Отсюда: регистрация для покупателя — единственный вход в заказ, и **путь к `/order` не должен теряться**.
`next` доносится со страницы входа в ссылку регистрации и сохраняется в каждой ветке ошибки формы.

### Аккаунты не удаляются (владелец, 24.11.2026)

На вопрос «удаление аккаунта: клиента целиком или заказы остаются?» ответ:
**«аккаунты не удаляются. При необходимости отдельно добавим»**.

| Что | Как |
|---|---|
| Кнопки «удалить аккаунт» | нет и не добавлять самовольно |
| Просьба закрыть аккаунт | закрываем доступ, удаляем фото, переписку и данные профиля |
| Записи о заказах | остаются: их требует хранить закон о бухгалтерском учёте |
| Политика на сайте | должна говорить ТО ЖЕ. Политика обещала удаление — расхождение исправлено 24.11.2026 |

**Правило шире аккаунтов:** если текст на сайте обещает действие, проверь, есть ли оно в коде.
Обещание без механизма — такой же дефект, как 500 на кнопке.

### Два правила, которые нельзя нарушать

1. **`_safe_next()`** — только внутренние пути (`/`-префикс, не `//`, без `\\`). Иначе это открытый редирект.
2. **Номер заказа НЕ ключ доступа.** Номера предсказуемы (`AA-261123-001`), раньше гость по номеру
   мог грузить фото в чужой заказ. Теперь номер ничего не даёт без сессии.

### Проверено (5 сценариев + 5 попыток обхода)

гость→вход 303 ✓ · вход с next→/order ✓ · регистрация с next→/order ✓ · без next→/cabinet ✓ ·
`next=//evil.com`, `/\\evil.com`, `https://evil.com`, `javascript:` → всё на /cabinet ✓
