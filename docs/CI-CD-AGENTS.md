# Бригада агентов и защита от поломок

Система должна ловить ошибки **до прода**, а не после. Принцип взят из исследования
Anthropic по состязательной проверке кода («Apollo-11»): **цель ревью формулируется ДО
написания кода**, иначе проверка подгоняется под готовое решение.

## Роли

| Агент | Что делает | Когда срабатывает |
|---|---|---|
| **Архитектор** | дробит задачу, формулирует критерии приёмки и цель ревью | до кода |
| **Программист** | пишет код в изолированной ветке | по плану |
| **Ревьюер** (чистый контекст) | ищет, как сломать решение; не видит замысла автора | после кода |
| **Тестировщик** | прогоняет тесты, nginx -t, поднимает контейнер и проверяет | после ревью |
| **Релиз-инженер** | деплой только из main, бесшовно, с откатом | после зелёных проверок |
| **Сторож (watchdog)** | следит за сайтом после деплоя, откатывает при падении | непрерывно |

Правило владельца: ревьюер и тестировщик работают в **отдельном контексте** — автор не проверяет
сам себя.

## Что мерим (DORA)

Скорость и стабильность не альтернативы — лучшие команды хороши в обоих.

| Метрика | Что значит для нас |
|---|---|
| Частота релизов | как часто main доезжает до прода |
| Время от коммита до прода | сколько задача ждёт проверок |
| Время восстановления | как быстро откатываемся при падении |
| **Доля неудачных релизов** | главная метрика — сколько деплоев сломало прод |
| Доля переделок | сколько работ возникло из-за инцидентов, а не из плана |

Цель: доля неудачных релизов → 0, время восстановления < 2 минут.

## Ворота (check gates)

Каждый PR проходит по порядку, следующее не наступает без предыдущего:

1. `python -c "import main"` — приложение **импортируется** (лова ломала прод)
2. `nginx -t` — конфиг валиден
3. Сборка образа
4. Подъём контейнера **под другим именем** + `/health` = 200
5. Живая проверка страниц (главная, лендинг, вход, кабинет)
6. Только теперь — замена продового контейнера

## Правила деплоя

- Деплой **только из main**, по тегу
- Новый контейнер стартует рядом, старый убирается после зелёного healthcheck
- `docker rename` запрещён — оставляет зомби с restart-политикой
- Откат: поднять предыдущий образ под тем же именем
