# Манифест 11 — Инпуты и формы

## Текущее состояние (обновлено 24.11.2026)
Формы есть — они живут в приложении, а не на статической главной:

| Форма | Где | Отправка |
|---|---|---|
| Заказ книги | `/order` | `POST /api/order`, multipart Form |
| Загрузка фото | `/order` | `POST /api/order/<номер>/photos`, поле `files` |
| Вход | `/login` | обычная POST-форма |
| Регистрация | `/register` | обычная POST-форма, согласие на ПДн проверяется на сервере |
| Смена пароля | `/settings` | `POST /api/password` |
| Настройки сайта | `/admin/settings` | обычная POST-форма |

На статической главной (`build/dist/index.html`) форм по-прежнему нет — там только ссылки и кнопки в мессенджеры.

## Правила для новых форм (действуют)
- Поле: input/textarea, Nunito 16px, padding 14px 18px, border 1.5px #DCD3F7, radius 16px, focus: border #4B4690 + тень.
- Кнопка отправки — .btn--primary (манифест 10).
- Отправка: только fetch на backend/на проксированный сервис форм; никакого mailto.
- Защита: honeypot-поле + rate-limit на nginx (limit_req), Cloudflare Turnstile вместо капчи.
- UI-правило владельца: никаких перезагрузок страницы — fetch + тост «Заявка отправлена».
- Никогда не хранить персональные данные детей (фото/имена) на сервере без явного согласия — 152-ФЗ.
